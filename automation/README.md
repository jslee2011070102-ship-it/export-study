# 문서작업 자동화 (프로토타입)

수출 거래 데이터를 한 곳에 두고 **서류를 생성**하고 **사고를 미리 잡는** 도구.

분석에서 나온 결론 두 가지를 그대로 구현한 것.

| 결론 | 구현 |
|---|---|
| **상업송장이 마스터 데이터** — C/I 가 틀리면 P/L, 수출신고서, C/O 가 함께 틀림 | 단일 JSON 에서 두 서류를 파생 |
| **실무 함정의 대부분은 서류 작성 시점에 잡을 수 있음** | 규칙 엔진으로 사전 검증 |

---

## 구성

| 파일 | 역할 |
|---|---|
| `schema.json` | 거래 마스터 데이터 스키마. `forms/수출서류_상업송장_포장명세서.xlsx` 의 `[입력]` 시트와 1:1 대응 |
| `validate.py` | **정합성 검증 엔진.** 서류를 만들기 전에 돌린다 |
| `generate.py` | JSON → Commercial Invoice / Packing List (xlsx) |
| `parse_declaration.py` | **수출신고필증(면장) 파서.** PDF → JSON + 송장 데이터와 대조 |
| `samples/sample.json` | 정상 샘플 |
| `samples/sample_broken.json` | 규칙이 실제로 잡는지 확인하는 오류 샘플 |
| `samples/수출신고필증_예시.txt` | 실제 발급본(식별정보 치환)의 pdftotext 결과. 파서 회귀 테스트용 |
| `samples/sample_필증대조.json` | 위 필증과 1:1 대응하는 송장 데이터 |

## 사용

```bash
pip install openpyxl

# 1) 검증 - 오류가 있으면 종료코드 1
python3 automation/validate.py automation/samples/sample.json

# 2) 서류 생성
python3 automation/generate.py automation/samples/sample.json -o out/
```

기준일을 바꿔 적재기한을 시뮬레이션할 수 있다.

```bash
python3 automation/validate.py automation/samples/sample.json --today 2026-09-20
```

CI 에 물리려면 `--json` 으로 결과를 받아 파이프에 태우면 된다.

### 수출신고필증 파싱

```bash
apt-get install -y poppler-utils      # pdftotext

# 필증에서 항목 뽑기
python3 automation/parse_declaration.py 필증.pdf -o 필증.json

# 송장 데이터와 대조
python3 automation/parse_declaration.py 필증.pdf --check 송장.json
```

유니패스 발급본은 텍스트 레이어가 있어 그대로 읽힌다. 스캔 이미지는 대상이 아니다.

뽑는 항목 — 신고번호/세관과/신고일자/신고구분/C/S구분, 신고자/수출대행자/수출화주/제조자/구매자와 각 부호, 거래구분/종류/결제방법, 목적국/적재항/운송형태/물품소재지, 란별 품명·거래품명·세번부호·순중량·포장갯수·신고가격(FOB)과 모델·규격 명세, 총중량/총포장갯수/총신고가격, 운임/보험료, **결제금액(인도조건-통화-금액)**, 적재의무기한/신고수리일자/발행번호.

## 검증 규칙

전부 [manual/부록C 실무함정 10선](../manual/부록C_실무함정_10선.md)과 법령 검증 결과에서 나온 것.

### 인코텀즈 (`INCO`)

| 코드 | 검사 |
|---|---|
| INCO-02 | 가격조건에 **지정장소**가 붙어 있는가 (`FOB` ✗ / `FOB BUSAN` ✓) |
| INCO-03 | CFR/CPT/CIF/CIP 인데 **운임 금액**이 있는가 — FOB 환산에 필요 |
| INCO-04 | CIF/CIP 인데 **보험료**가 있는가 — 매도인 부보 의무 |
| INCO-05 | EXW 경고 — 수출통관이 매수인 의무임을 상기 |
| INCO-06 | 인코텀즈 **2020** 명시 여부 |
| INCO-07 | 11개 규칙에 없는 표기 차단 (예: 2010 의 `DAT`) |
| INCO-08 | **해상 전용 규칙(FAS/FOB/CFR/CIF)을 항공/육상 건에 사용** — 대체 규칙 제시 |
| INCO-09 | 해상 전용 규칙을 **컨테이너 화물**에 사용 — FCA/CPT/CIP 권고 |
| INCO-10 | C 그룹인데 **인도장소(위험분기점)** 미지정 — 뒤 지명은 비용분기점임 |
| INCO-11 | D 그룹 — 목적지까지 매도인 위험. 운송보험 권고 |
| INCO-12 | DPU — 유일한 매도인 양하의무. 하역 수단 확인 |
| INCO-13 | DDP — 수입국 수입자 자격/부가세 환급 확인 |

### 품목 (`ITEM`)

| 코드 | 검사 |
|---|---|
| ITEM-01 | 품명이 `PARTS`, `GOODS` 처럼 **HS 분류 불가한 표기**가 아닌가 |
| ITEM-02 | **총중량 ≥ 순중량** 인가 |
| ITEM-03 | 총중량 누락 — 미선적 처리의 주원인 |

### 당사자 / 통관 (`PARTY`, `CUS`)

| 코드 | 검사 |
|---|---|
| PARTY-02 | 상호에 소문자 혼입 — C/O 는 **대소문자까지** 송장과 일치해야 함 |
| PARTY-03/04 | 통관고유부호 / **해외거래처부호** — 없으면 수출신고 불가 |
| CUS-01 | **물품소재지** — 사업장 주소로 신고하면 조사 대상 |
| CUS-03 | 제조자 미상 — FTA C/O 발급 곤란 + 환급 제한 |

### 적재기한 (`LOAD`) — 관세법 제251조

| 코드 | 검사 |
|---|---|
| LOAD-01 | 기한 **경과** — 200만원 이하 과태료 + 수출신고 수리 취소 가능 |
| LOAD-02 | **D-7 이내** — 연장은 기한 내에만 신청 가능하므로 이 시점이 마지막 기회 |
| LOAD-03 | 정상. 남은 일수 표시 |

### 원산지 / FTA (`CO`)

| 코드 | 검사 |
|---|---|
| CO-01/02 | **발급형식 불일치** — 기관발급 협정에 자율발급을 지정했는가 (FTA특례법 시행규칙 §7) |
| CO-03 | 해당 협정의 **미소기준** 안내 (확인된 6개 협정) |
| CO-05/06 | 한-EU / 한-영 **6천유로** 초과 시 인증수출자 필요 |
| CO-07 | HS 코드로 **품목별 원산지결정기준 자동 조회** ([data/fta_psr.csv](../data/fta_psr.csv) 4,831행) |

### 수출신고필증 (`DEC`) — parse_declaration.py

| 코드 | 검사 |
|---|---|
| DEC-01~03 | 인도조건 / 통화 / 송품장부호가 **송장과 일치**하는가 |
| DEC-04 | 결제금액 = 송장 품목 합계 |
| DEC-05 | 총중량 일치 (오차 0.5kg) |
| DEC-06 | 세번 6단위 누락 — FTA 원산지판정 기준이 됨 |
| DEC-11 | 적재의무기한이 관세법 제251조 + 제8조제3항 계산과 일치하는가 |
| DEC-12 | 적재기한 경과 / D-7 경보 |
| DEC-20~22 | 인도조건 11개 규칙 여부, C 그룹 운임/보험료 기재 누락 |
| DEC-23 | 제조자 미상 신고 |
| DEC-24 | 모델·규격 금액 합계 = 총신고가격(FOB) |

### 결제 (`PAY`)

| 코드 | 검사 |
|---|---|
| PAY-01/02 | 결제방법 코드와 결제조건 문구의 **일관성** |
| PAY-03 | **전액 사후송금** 감지 → 신용조사/무역보험 검토 안내 |
| PAY-04 | 신용장 거래면 **Master B/L** 필요 안내 |

## 동작 확인

정상 샘플은 오류 0 / 경고 0 으로 통과하고, 일부러 망가뜨린 샘플에서 **10개 오류 + 5개 경고**를 잡는 것을 확인했다.

```
✖ [INCO-02] 가격조건에 지정장소가 없다: "CIF"
✖ [INCO-03] CIF 조건인데 운임 금액이 없다.
✖ [INCO-08] CIF 는 해상/내수로 전용인데 운송방식이 항공 이다.
✖ [ITEM-01] 1번 품목의 품명이 모호하다: "PARTS"
✖ [ITEM-02] 2번 품목의 총중량(100.0)이 순중량(160)보다 작다.
✖ [PARTY-04] 수입자 해외거래처부호가 없다.
✖ [CUS-01] 물품소재지가 없다.
✖ [LOAD-01] 적재기한이 5일 지났다. (기한 2026-08-31)
✖ [CO-01] 한-베트남 FTA 은 기관발급 협정이다. 자율발급 불가.
```

생성 문서도 값을 검증했다 — `1,200 × 3.50 = 4,200`, 총액 `USD 7,560.00`, 포장 `90 CTNS`, N.W. `340kg`.

## 한계와 다음 단계

| 항목 | 상태 |
|---|---|
| `generate.py` 의 수식 계산값 | openpyxl 은 수식 문자열만 쓴다. 엑셀에서 열면 자동 계산되지만, **프로그램으로 값을 읽으려면 recalc 가 필요** |
| PDF 출력 | 미구현. LibreOffice 변환 또는 별도 렌더러 필요 |
| 원산지증명서 생성 | 협정별 서식이 달라 미구현. [공식서식](../forms/공식서식/) 참고 |
| 수출신고필증 파싱 | **구현.** 실제 발급본으로 검증 완료. 스캔 이미지 PDF 는 미지원(OCR 필요) |
| 공휴일표 | `data/공휴일.csv` 2025~2027. 음력 기반(설/추석/부처님오신날)은 `[검증]` 표시. **연 1회 갱신 필요** |
| 유니패스 연동 | 미구현 |
| 코드값 검증 (거래구분/신고구분 등) | 관세청 **통계부호표** 확보 후 추가 가능 |

우선순위 제안.

1. **PDF 출력** — 바이어에게 바로 보낼 수 있는 형태
2. **통계부호표 확보** — 거래구분/신고구분/C/S/세관 코드값 검증
3. 거래 데이터 저장소 (지금은 JSON 파일 단위)
