# 문서작업 자동화 (프로토타입)

수출 거래 데이터를 한 곳에 두고 **서류를 생성**하고 **사고를 미리 잡는** 도구.

분석에서 나온 결론 두 가지를 그대로 구현한 것.

| 결론 | 구현 |
|---|---|
| **상업송장이 마스터 데이터** — C/I 가 틀리면 P/L, 수출신고서, C/O 가 함께 틀림 | 단일 JSON 에서 두 서류를 파생 |
| **실무 함정의 대부분은 서류 작성 시점에 잡을 수 있음** | 규칙 엔진으로 사전 검증 |

---

## 구성

| 파일 | 역할 |
|---|---|
| `schema.json` | 거래 마스터 데이터 스키마. `forms/수출서류_상업송장_포장명세서.xlsx` 의 `[입력]` 시트와 1:1 대응 |
| `validate.py` | **정합성 검증 엔진.** 서류를 만들기 전에 돌린다 |
| `build_template.py` | **템플릿 생성.** 레이아웃/서식/수식/인쇄설정을 전부 여기서 정의 |
| `generate.py` | JSON → 템플릿의 `[입력]` 시트를 채워 **xlsx + PDF 2장** 생성 |
| `parse_declaration.py` | **수출신고필증(면장) 파서.** PDF → JSON + 송장 데이터와 대조 |
| `co_rules.py` | 협정 25개의 원산지증명서 발급방식/문안. FTA특례법 시행규칙 제15조 |
| `generate_co.py` | **원산지증명서 / 원산지신고서 문안** 생성 |
| `samples/sample.json` | 정상 샘플 |
| `samples/sample_broken.json` | 규칙이 실제로 잡는지 확인하는 오류 샘플 |
| `samples/수출신고필증_예시.txt` | 실제 발급본(식별정보 치환)의 pdftotext 결과. 파서 회귀 테스트용 |
| `samples/sample_필증대조.json` | 위 필증과 1:1 대응하는 송장 데이터 |

## 사용

```bash
pip install openpyxl
apt-get install -y libreoffice-calc poppler-utils    # PDF 출력용

# 1) 검증 - 오류가 있으면 종료코드 1
python3 automation/validate.py automation/samples/sample.json

# 2) 서류 생성 (xlsx + PDF)
python3 automation/generate.py automation/samples/sample.json -o out/
#   out/SY-2026-0001_수출서류.xlsx   [입력] + C/I + P/L. 편집 가능
#   out/SY-2026-0001_CI.pdf          Commercial Invoice 1장
#   out/SY-2026-0001_PL.pdf          Packing List 1장

python3 automation/generate.py <file.json> -o out/ --no-pdf    # xlsx 만
```

### 서류 생성 방식

`generate.py` 는 **레이아웃을 그리지 않는다.** `forms/수출서류_상업송장_포장명세서.xlsx` 템플릿의
`[입력]` 시트 좌표에 값만 써넣고, 서식/수식/인쇄설정은 템플릿이 갖고 있다.

```
build_template.py ──▶ forms/수출서류_상업송장_포장명세서.xlsx   (템플릿)
                                    │
거래 데이터 JSON ──▶ generate.py ──▶ [입력] 시트를 채움
                                    │
                                    ├─▶ {invoice}_수출서류.xlsx
                                    └─▶ soffice → PDF → 제목으로 페이지 분리 → CI.pdf / PL.pdf
```

레이아웃을 고치려면 **`build_template.py` 를 고치고 다시 돌릴 것.** xlsx 를 직접 편집하면
다음 생성 때 덮어써진다. 품목은 최대 15행이고, 늘리려면 `build_template.py` 의 `품목_끝` 을 조정한다.

PDF 는 LibreOffice 가 변환 시점에 수식을 계산하므로 별도 recalc 가 필요 없다. 다만 시트를
숨겨도 PDF 변환에서 제외되지 않아, 워크북 전체를 변환한 뒤 **각 페이지의 제목**(`COMMERCIAL
INVOICE` / `PACKING LIST`)으로 페이지를 갈라 문서별 PDF 를 만든다.

기준일을 바꿔 적재기한을 시뮬레이션할 수 있다.

```bash
python3 automation/validate.py automation/samples/sample.json --today 2026-09-20
```

CI 에 물리려면 `--json` 으로 결과를 받아 파이프에 태우면 된다.

### 수출신고필증 파싱

```bash
apt-get install -y poppler-utils      # pdftotext

# 필증에서 항목 뽑기
python3 automation/parse_declaration.py 필증.pdf -o 필증.json

# 송장 데이터와 대조
python3 automation/parse_declaration.py 필증.pdf --check 송장.json
```

유니패스 발급본은 텍스트 레이어가 있어 그대로 읽힌다. 스캔 이미지는 대상이 아니다.

뽑는 항목 — 신고번호/세관과/신고일자/신고구분/C/S구분, 신고자/수출대행자/수출화주/제조자/구매자와 각 부호, 거래구분/종류/결제방법, 목적국/적재항/운송형태/물품소재지, 란별 품명·거래품명·세번부호·순중량·포장갯수·신고가격(FOB)과 모델·규격 명세, 총중량/총포장갯수/총신고가격, 운임/보험료, **결제금액(인도조건-통화-금액)**, 적재의무기한/신고수리일자/발행번호.

### 원산지증명서

```bash
python3 automation/generate_co.py automation/samples/sample.json -o out/ --협정 한-영국
python3 automation/generate_co.py <file.json> --협정 한-베트남      # 안내만 출력
```

**협정마다 성격이 다르다.** FTA특례법 시행규칙 제15조 기준으로 3가지.

| 방식 | 뜻 | 이 도구가 하는 일 |
|---|---|---|
| **기관발급** | 세관(유니패스)/상공회의소가 발급 | **생성하지 않음.** 발급 경로와 구비서류 안내 |
| **서식형** | 정해진 별지서식을 수출자가 작성 | **한-미만 구현** (별지 제17호서식) |
| **문안형** | 별도 서식 없이 상업송장 등에 규정된 문안을 기재 | 한-영국 / 한-EU |

협정별 분류 —

| 방식 | 협정 |
|---|---|
| 기관발급 | 싱가포르 / 아세안 / 인도 / 베트남 / 중국 / 인도네시아 |
| 서식형 | 칠레 / 페루 / **미국** / 콜롬비아 / 호주 / 캐나다 / 중미 |
| 문안형 | EFTA / **EU** / 튀르키예 / 뉴질랜드 / **영국** |
| 혼합 | RCEP / 이스라엘 / 캄보디아 / 필리핀 / UAE / 에콰도르 |

**출처 확보 상태**

| 항목 | 상태 |
|---|---|
| 협정별 발급방식 25개 | **확정** — 시행규칙 제15조 전문 |
| 한-영국 문안 (영문/국문/작성방법) | **확정** — 별표 20의2 전문 |
| 한-미 기재사항 8개 | **확정** — 제15조제8항제2호 전문 |
| **한-EU 문안** | **`[검증]`** — 별표 17 이 국가법령정보센터에 기계판독 형태로 없음. 한-영국(별표 20의2) 문안을 근거로 생성하되 출력에 경고를 찍는다 |
| EFTA / 튀르키예 / 뉴질랜드 / 이스라엘 / 필리핀 / UAE / 에콰도르 문안 | 미확보 → 생성하지 않고 안내만 |

기관발급 협정에 대해 **수출자가 만든 문서는 효력이 없다.** 그래서 생성 자체를 막고
유니패스/상의 발급 경로와 구비서류를 안내한다.

## 동작 확인

정상 샘플은 오류 0 / 경고 0 으로 통과하고, 일부러 망가뜨린 샘플에서 **10개 오류 + 5개 경고**를 잡는 것을 확인했다.

```
✖ [INCO-02] 가격조건에 지정장소가 없다: "CIF"
✖ [INCO-03] CIF 조건인데 운임 금액이 없다.
✖ [INCO-08] CIF 는 해상/내수로 전용인데 운송방식이 항공 이다.
✖ [ITEM-01] 1번 품목의 품명이 모호하다: "PARTS"
✖ [ITEM-02] 2번 품목의 총중량(100.0)이 순중량(160)보다 작다.
✖ [PARTY-04] 수입자 해외거래처부호가 없다.
✖ [CUS-01] 물품소재지가 없다.
✖ [LOAD-01] 적재기한이 5일 지났다. (기한 2026-08-31)
✖ [CO-01] 한-베트남 FTA 은 기관발급 협정이다. 자율발급 불가.
```

생성 문서도 값을 검증했다 — `1,200 × 3.50 = 4,200`, 총액 `USD 7,560.00`, 포장 `90 CTNS`, N.W. `340kg`.
