# 운송서류 — B/L, AWB, Surrender, D/O

수출설명서 10장(포워더/선적)의 원본 자료. 무꿈사TV 운송/물류 10편(자막) 및 관련 블로그에서 추출.

주의 — 자동자막 기반이라 구조와 논리만 복원함. 서식 항목명/약관 문구는 실제 B/L 양식 대조 필요.

---

## 1. 운송 당사자 구조

| 용어 | 의미 |
|---|---|
| 실화주 | 실제 물품의 주인 (수출자/수입자) |
| 송하인 (Shipper) | 운송인에게 물품을 넘기는 자 |
| 수하인 (Consignee) | 목적지에서 물품을 받는 자 |
| 착화통지처 (Notify Party) | 도착통지를 받을 자. 통상 실제 수입자 |
| 실제운송인 (Actual Carrier) | 선사/항공사. 운송수단을 직접 보유 |
| 계약운송인 (Contracting Carrier) | 포워더. 운송을 주선. 운송주선업자 |
| 콘솔(Consolidator) | LCL 혼재를 전문으로 하는 업체. 규모가 포워더보다 큰 경우가 많음 |

포워더를 쓰는 이유 — 소량 화주가 선사와 직접 계약하기 어렵고, 소량화물을 모아 컨테이너 단위로 만들어야 운임 경쟁력이 생김. 영세 포워더는 자체 혼재가 어려워 콘솔 업체에 재의뢰하는 구조.

## 2. Master B/L vs House B/L

| 구분 | Master B/L | House B/L |
|---|---|---|
| 발행자 | **선사** → 포워더 앞 | **포워더** → 각 화주 앞 |
| 다른 이름 | Direct B/L / Line B/L / Groupage B/L | Forwarder's B/L |
| 선사에 대한 직접청구권 | **있음** | 없음 |
| 목적지 화물 인도 | 선사는 Master 소지자(포워더)에게만 인도 | 포워더가 CFS 에서 분해 후 House 소지자에게 인도 |

LCL 흐름 — 포워더가 화주 10인의 LCL 을 모아 FCL 1대로 만들어 선사에 운송 의뢰. 선사는 그 안에 누구 화물이 몇 건인지 관심 없음. 선사는 컨테이너 단위로 Master 를 발행하고, 포워더는 화주별로 House 를 발행.

### Master B/L 이 필요한 경우

| 상황 | 사유 |
|---|---|
| **신용장 방식** | 개설은행이 B/L 을 담보로 잡는데, House 는 선사에 대한 직접청구권이 없어 담보 기능이 약함. 예외 없이 Master 요구 |
| 특정 국가 정책 | 수입국 규정상 Master 를 요구하는 경우 존재 |

대응 — 선사와 직접 계약할 필요 없음. 포워더에게 "수입자가 Master B/L 을 요구한다"고 전달하면 포워더가 처리.

### 구분하는 4가지 방법

| # | 확인 위치 | Master | House |
|---|---|---|---|
| 01 | 우측 상단 발행인 로고 | 선사명 (`SHIPPING`, `LINE`, `~ Co., Ltd.` 등 선사 상호) | 물류업체명 (`LOGISTICS`, `INTERNATIONAL`, `FORWARDING`) |
| 02 | 하단 서명란 | `as Carrier` / `as Agent for(on behalf of) the Carrier` | `acting as Carrier` 또는 회사명만 기재 |
| 03 | 유니패스 화물추적 | Master B/L 번호 입력란에서 조회됨 | House B/L 번호 입력란에서 조회됨 |
| 04 | 선적란 (Place of Receipt/Delivery) | `CY-CY` | `CFS-CFS` |

주의 — 포워더가 발행했다고 무조건 House 가 아님. 포워더가 **선사의 대리인 자격**(`as Agent on behalf of the Carrier`)으로 서명하면 Master 로 처리됨. 신용장에서 Master 가 필요할 때 포워더에게 이 서명 형식으로 요청하는 방식이 실무에서 사용됨.

02번 서명란 확인이 가장 확실하고, 03번 유니패스 조회가 가장 객관적.

## 3. Surrender / SWB / L/G

원본 B/L 은 **권리증권**. 소지자가 화물의 주인이 되므로, 수하인은 원본을 수령해 운송인에게 반환해야 화물을 찾을 수 있음.

| 방식 | 내용 |
|---|---|
| 원본 B/L | 송하인이 특송 등으로 수하인에게 원본 송부 → 수하인이 운송인에게 반환 |
| **Surrender** | 송하인이 원본을 운송인에게 반납하고 권리증권 기능을 포기. 수하인은 본인확인만으로 화물 수령 |
| **SWB** (Sea Waybill) | 애초에 권리증권이 아닌 운송장. 원본 유통이 필요 없음 |
| **L/G** (수입화물선취보증서) | 원본이 아직 도착하지 않았을 때 은행 보증으로 먼저 화물을 찾는 방식. 신용장 거래에서 사용 |

Surrender 여부 확인 — B/L 면에 `SURRENDERED` / `SURRENDER` 표기, `COPY` 도장, 또는 `TELEX RELEASE` 표기. **Telex Release 와 Surrender 는 같은 말**.

실무 빈도 — 근거리(중국/일본 등) 거래에서는 원본보다 Surrender 가 압도적. 원본 B/L 이 화물보다 늦게 도착하는 문제 때문.

신용장 거래에서의 차이 — 원본 B/L 이 은행을 통해 이동해야 하므로 Surrender/SWB 를 쓸 수 없음. 대신 원본 미도착 시 **L/G(은행 보증)** 를 사용.

## 4. B/L vs AWB

| 항목 | B/L (선하증권) | AWB (항공화물운송장) |
|---|---|---|
| 운송수단 | 해상 | 항공 |
| 유가증권성 | **권리증권** | 아님. 단순 운송장 |
| 원본 유통 | 필요 | 불필요 |
| 화물 인도 | 원본 회수 또는 Surrender 후 | 수하인 본인확인으로 인도 |

AWB 가 권리증권이 아닌 이유 — 항공은 운송기간이 짧아 원본이 화물보다 늦게 도착하는 문제가 구조적으로 발생. 유통증권으로 설계할 실익이 없음.

## 5. 목적지 화물 인수 흐름

```
도착통지서(A/N) 수령
  → 유니패스에서 운송서류 번호로 입항 확인
  → 운임인보이스 수령 및 정산
  → 수입신고 (관세사에 C/I, P/L, B/L 사본, 운임인보이스 전달)
  → 관세 납부 및 신고수리
  → D/O(인도지시서) 발행
  → 화물 반출
```

- 유니패스 조회는 **운송인이 세관에 적하목록을 제출한 이후**부터 가능. 도착통지서를 받았는데 조회가 안 된다고 무역사기를 의심할 필요 없음.
- **운임인보이스는 인코텀즈 조건과 무관하게 반드시 요청.** CFR 등 매도인이 운임을 내는 조건에서도 THC(터미널화물처리비)/Documentation Fee 등 수입국 정산 항목이 빈번히 발생. 없으면 "없다"고 관세사에게 알려줘야 통관 지연이 없음.

## 6. 컨테이너/터미널 용어

| 용어 | 의미 |
|---|---|
| FCL | Full Container Load. 컨테이너 단위 화물. **CY 로 직행** |
| LCL | Less than Container Load. 소량화물. **CFS 경유** (혼재/분해 작업) |
| CY | Container Yard. 컨테이너 장치장 |
| CFS | Container Freight Station. 혼재 작업 창고 |
| DEM | Demurrage. 컨테이너를 터미널에서 반출하지 않아 발생하는 체화료 |
| DET | Detention. 컨테이너를 반납하지 않아 발생하는 지체료 |
| VGM | 컨테이너 총중량 신고 제도 |
| THC / BAF | 터미널화물처리비 / 유류할증료. 운임인보이스의 대표 부대항목 |

## 7. 수출설명서 집필 시 처리 방침

| 항목 | 방침 |
|---|---|
| 수출자 관점 정리 | 수출자는 B/L 을 **받는** 쪽. 발행 이후 확인/전달이 핵심이므로 "받은 B/L 을 어떻게 검증하는가"로 서술 |
| Master/House 판별 4법 | 표 그대로 체크리스트화. 자동화 계층 2(파싱)의 판별 규칙으로도 사용 |
| Surrender | 근거리 거래 실무 기본값으로 서술하되, 신용장 거래에서는 불가함을 반드시 병기 |
| 보강 필요 | B/L 서식 항목별 해석(상단/중단/하단)은 채널에 전용 영상 존재. 실제 양식 확보 후 필드 대조 필요 |
