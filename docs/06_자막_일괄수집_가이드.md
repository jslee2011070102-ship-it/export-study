# 자막 64편 일괄 수집 가이드

옵시디언 Web Clipper 를 64번 누르는 대신, PC 에서 스크립트 한 번으로 동일한 포맷의 `.md` 를 볼트에 바로 떨어뜨리는 방법.

전제 — YouTube 가 정상적으로 보이는 PC 에서 실행. (분석 컨테이너는 YouTube 워치 페이지가 차단되어 자막을 못 받음. 그래서 이 작업만 로컬에서 처리)

---

## 1. 준비

```powershell
pip install yt-dlp
```

Python 이 없으면 python.org 에서 3.9 이상 설치 (설치 시 `Add python.exe to PATH` 체크).

리포를 받아둔다.

```powershell
git clone https://github.com/jslee2011070102-ship-it/export-study
cd export-study
```

## 2. 시험 실행 — 1편만

먼저 1편만 돌려서 결과물이 기존 클리핑과 같은지 눈으로 확인.

```powershell
python scripts/fetch_transcripts.py --urls data/need_transcript_urls.txt --out .\test --limit 1
```

`test\` 폴더에 `.md` 하나가 생김. 열어서 아래 3가지 확인.

| 확인 항목 | 정상 |
|---|---|
| 프론트매터 | `title` / `source` / `published` / `tags: clippings` 존재 |
| 챕터 | `### 인코텀즈...` 형태의 `###` 헤딩이 중간중간 삽입됨 |
| 자막 | `**7:49** · 송장을 가장 잘 작성하는...` 형태로 25초 단위 블록 |

## 3. 전체 실행 — 볼트에 직접 저장

경로는 본인 볼트 위치로 교체.

```powershell
python scripts/fetch_transcripts.py `
  --urls data/need_transcript_urls.txt `
  --out "C:\경로\second-brain\raw\clippings\무역"
```

- 64편 기준 소요 5~10분 (영상당 2초 대기 포함)
- **이미 있는 파일은 건너뜀.** 중간에 끊겨도 다시 실행하면 이어서 받음
- 차단이 걱정되면 `--sleep 5` 로 대기시간 증가

## 4. 푸시

옵시디언 우측 Git 패널에서 커밋 → 푸시. 또는 터미널에서.

```powershell
cd "C:\경로\second-brain"
git add raw/clippings
git commit -m "무꿈사 무역영상 자막 64편 추가"
git push
```

푸시 후 알려주면 분석에 반영.

## 옵션 — 스크립트 없이 yt-dlp 만으로

포맷은 다르지만 자막 텍스트만 빠르게 뽑는 방법.

```powershell
yt-dlp --skip-download --write-auto-subs --sub-langs ko --sub-format vtt `
       --batch-file data\need_transcript_urls.txt -o "%(title)s.%(ext)s"
```

`.vtt` 파일로 떨어짐. 옵시디언 클리핑 포맷은 아니지만 내용 분석에는 충분함.

---

## 자주 나는 오류

| 증상 | 원인/조치 |
|---|---|
| `yt-dlp 가 없다` | `pip install yt-dlp` |
| `한국어 자막 없음` | 해당 영상에 한글 자막 미제공. 건너뛰고 진행됨. 실패 목록은 실행 끝에 집계 |
| `HTTP Error 429` | 요청 과다. `--sleep 10` 으로 재실행. 이미 받은 건 건너뛰므로 손해 없음 |
| 메타데이터 실패 반복 | yt-dlp 가 구버전일 가능성. `pip install -U yt-dlp` |
| 파일명이 깨짐 | 윈도우 금지문자는 자동 치환됨. 그래도 문제면 `--out` 경로에 한글/공백을 줄일 것 |

---

## 왜 옵시디언 일괄 클리핑이 안 되는가

- Obsidian Web Clipper 에 배치 모드 없음. 탭 하나당 한 번씩 눌러야 함
- 크롬 탭 64개를 한꺼번에 띄우는 확장은 있으나, 클리핑 자체는 여전히 64번 수작업
- 유튜브 자막 패널이 로드된 뒤에 눌러야 자막이 잡히므로 자동화가 더 불안정

결론 — 스크립트가 정확도/속도 양쪽에서 우위.
